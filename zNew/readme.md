# 🚚 Корпоративный веб-портал «ТрансЛогистик» (ТЛК) — MVP

## 📖 Описание проекта
«ТрансЛогистик» — корпоративный веб-портал для автоматизации приема и управления заявками на грузоперевозки. 
В рамках учебного курса развернут MVP, обеспечивающий ролевую изоляцию (Клиент, Менеджер, Водитель), строгий жизненный цикл заявки и неизменяемость аудиторского следа.

---

## ⚠️ Архитектура учебного полигона
Проект работает по трёхзвенной архитектуре. Важно понимать, где и что запущено:

1. **Backend (Серверная часть):** 
   * Уже развернут и работает на удаленном сервере преподавателя по адресу: `http://10.2.9.17:8000`. 
   * Студентам **не нужно** запускать бэкенд локально. Код в папке `BackStud01/` предоставлен только для ознакомления.
2. **База данных (PostgreSQL):** 
   * Находится на том же сервере (`10.2.9.17`, порт `5432`). 
   * Данные всех 15 студентов физически разделены по персональным схемам (`tlk01`, `tlk02` ... `tlk15`).
3. **Frontend (Клиентская часть):** 
   * Запускается **локально** на вашем компьютере. 
   * Код уже настроен на работу с удаленным сервером.

## 🔄 Как это работает: Взаимодействие Frontend и Backend
Поскольку все 15 студентов обращаются к **одному и тому же** бэкенду на порту `8000`, возникает вопрос: как бэкенд понимает, кому отдать данные и в какую схему БД записать новую заявку?

Ответ кроется в **HTTP-заголовках**. Вот пошаговый цикл взаимодействия:

1. **Авторизация:** Вы вводите логин `stud03`. Frontend понимает, что ваша схема в БД называется `tlk03`.
2. **Формирование запроса:** Когда Frontend делает любой запрос к API (например, `GET /orders`), он автоматически добавляет к HTTP-запросу специальный заголовок:
   `X-User-Schema: tlk03`
3. **Обработка на Backend:** Удаленный бэкенд перехватывает ваш запрос, читает заголовок `X-User-Schema` и подставляет его значение в SQL-запрос. 
   Вместо абстрактного `SELECT * FROM orders`, бэкенд выполняет `SELECT * FROM tlk03.orders`.
4. **Ответ:** Бэкенд возвращает данные строго из вашей схемы `tlk03`. Данные других студентов (`tlk01`, `tlk02`) к вам не попадут.

**Важно:** Вся магия подстановки этого заголовка уже написана в файле `Frontend/app.js` (в функциях `apiFetch` и `login`). Вам не нужно писать этот код самостоятельно, но вы должны понимать этот механизм для прохождения тестирования и отладки.

## 🚀 Пошаговая инструкция для студента

### Шаг 1. Клонирование репозитория
Откройте терминал и выполните:
```bash
git clone https://github.com/pd196505/WEB_Resourses.git
cd WEB_Resourses
```

### Шаг 2. Настройка базы данных
Вам нужно создать свою схему и наполнить её данными.
1. Откройте **pgAdmin** и подключитесь к серверу:
   * Host: `10.2.9.17`
   * Username: `studXX` (ваш номер, например `stud03`)
   * Password: *(уточните у преподавателя)*
2. Откройте Query Tool и последовательно выполните три SQL-скрипта из корня репозитория:
   * `CreateShemas.sql` — создаст схему `tlkXX`.
   * `CreateTable.sql` — создаст таблицы внутри вашей схемы.
   * `TestData.sql` — добавит тестовых пользователей и заявки.

### Шаг 3. Запуск Frontend
1. Откройте папку `Frontend/` в редакторе кода (VS Code).
2. Запустите локальный сервер через расширение **Live Server** (или просто откройте `index.html` в браузере).
3. Убедитесь, что адресная строка начинается с `http://localhost...` или `http://127.0.0.1...` (это критично для CORS).

### Шаг 4. Тестирование и проверка изоляции
1. На экране входа введите:
   * Роль: `client` (или `manager`, `driver`)
   * Логин: `studXX` (ваш номер)
   * Пароль: `123`
2. Создайте заявку. 
3. Попросите соседа войти под его логином (`studYY`). Убедитесь, что он не видит вашу заявку, так как его Frontend отправляет заголовок `X-User-Schema: tlkYY`, и бэкенд обращается к его изолированной схеме.

## 🛠️ Отладка и проверка запросов (F12)

Если что-то не работает (например, бэкенд возвращает ошибку 403 или пустые данные), используйте инструменты разработчика в браузере:

1. Нажмите `F12` и перейдите на вкладку **Network (Сеть)**.
2. Обновите страницу или создайте заявку.
3. Кликните на любой запрос к API (например, `orders`).
4. Посмотрите раздел **Request Headers (Заголовки запроса)**.
5. Убедитесь, что там присутствует строка: `X-User-Schema: tlkXX`. Если её нет или она неверная — бэкенд не сможет найти ваши данные.
